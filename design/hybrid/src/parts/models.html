Local models

Models that run on this Mac, woken when needed and put to sleep when idle, for private data that shouldn't reach Claude. Drawn 12 Oct 2026 for the owner's approval.

A local model is a tool, not a provider: Claude is still the only chat. An agent with private files to process hands them to a local model by path, and only the model's answer comes back, so what the files hold never enters Claude's context. CONTROL starts each model as its own llama-server process, keeps its PID, port and memory on record, and puts it to sleep after 10 idle minutes. A model is asleep (not running), waking (loading, then reading its system prompt once so it's cached) or ready. Before a wake, CONTROL checks free memory and keeps 15 GB back, and anything over 40 GB asks you first. Quitting CONTROL puts every model to sleep, and after a crash CONTROL kills the ones it started, so no model is left eating memory with no one watching it.

M1Awake, in the sidebar

While a model is awake, a note in the update note's form sits under the update note: its lamp, its name and its state, and Sleep. There's one note per awake model, and none while every model is asleep. A click on the name opens Settings › Local models. Sleep ends the process at once. While a model is still waking, Sleep stops the load.

In the thread, a local model is a tool call like any other. The row names the model and what it was given (the count of files, never their contents), and the meta is the time and the answer's length.

M2Settings › Local models

The models you've registered, with what each is doing. An awake row shows its PID, port and resident memory, and when it will sleep. The bar is the Mac's memory: other apps, CONTROL's models, what's free, and the 15 GB kept back, with the swap in use at the end. Selecting a row opens its settings. The command line is filled in from the file when you add it (your serve.sh flags here), and you can edit it. CONTROL owns the host and the port, so the model listens on this Mac only. The system prompt is read once at every wake, so each call after it starts warm. A model sleeps after 10 idle minutes unless you change it. Changes apply at its next wake.

M3Adding a model

Add looks for GGUF files in ~/models and the Hugging Face cache, the format llama-server runs. A vision projector found beside a model is attached to it, not listed on its own. Browse picks any other file. Adding and editing are desktop only, because a model's command runs on the Mac.

M4Waking from a chat

An agent wakes a model when it calls one that's asleep: the call waits through the wake, then runs. Over 40 GB, the wake asks you first, in that chat, the way a permission request does: the chat needs you until you answer, and only your Approve wakes it. If the wake would leave less than 15 GB free, or the Mac is already using swap, CONTROL refuses it, the agent gets the numbers back, and nothing else is touched. CONTROL doesn't put other models to sleep to make room.

M5The phone

The phone shows the same note at the top of the chat list while a model is awake, and Settings › Local models lists every model with Wake and Sleep. The same memory check and the same over-40 GB ask apply there. Adding a model and editing its command are on the Mac only.
